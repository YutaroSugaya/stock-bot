# データモデル

本番 Postgres スキーマの SSOT は [`migrations/0001_init.up.sql`](../../migrations/0001_init.up.sql)。
現リポの in-memory リポジトリ(`backend/internal/adapter/repository/`)は同じ形を写す。

## main テーブル
- **strategy_configs** — 戦略 config(凍結元)。`(symbol, mode, strategy_name) WHERE status='active'` の partial unique index で **1 銘柄 × 1 戦略につき** active 1 件保証(migration 0014。入口が同一で出口だけ違う 2 アームを同じ銘柄に並べられるようにするため)。**live だけは 1 銘柄 1 active** — `mode='live_config'` 限定の partial unique index `strategy_configs_active_live_uidx` が DB 側でも縛る。`raw_yaml` に config **全文**を保存(「その時どの config で動いていたか」の監査。起動時 `ensureCfg` が `YAMLText()` を渡す。既存行は raw_yaml が空のときのみ backfill)。`advisor_run_id`(0007・NULL 許容)= この config を書いた advisor run への参照(runtime が刻む。LLM の YAML からは注入不可 `yaml:"-"`。人手/テスト/sentinel は NULL)。
- **positions** — 建玉。株固有のカラム: `holding_mode` / `exec_kind` / `tick_size_at_entry`。`config_id NOT NULL REFERENCES strategy_configs`(孤児化防止)。`status ∈ {OPEN,CLOSING,CLOSED}`。`source ∈ {bot,manual,external_broker}`。**exit 幾何は建玉時に全て凍結**: TP/SL/MaxHold/ratchet に加え `extension_*` / `early_exit_*`(migration 0003 で追加。無いと Postgres 運用時のみ `EvaluateExit` の延長/早期利確枝が死に、backtest と実行が静かに乖離する)。`peak_unrealized_jpy` / `trough_unrealized_jpy`(0010)は凍結値ではなく**実行中に更新される記録**(MFE/MAE・円/株)で、**ratchet を持たない建玉でも更新する**(0010 以前は ratchet 建玉だけだった)。どの決済規則も trough を読まない — トレールを事後に反実仮想で測るための材料。`ratchet_floor_at_arm`(0013・**default false**)は「トレールの床が効く建玉か」を entry 時に凍結するフラグ。床は凍結値から**実行時に**計算されるので、これが無いとコード変更が既存の建玉にもその場で効き、測っている対象が途中で入れ替わる。**新規建玉は true / 既存行は false のまま**。`strategy_name`(0015・default `''`)は凍結 config の戦略名の写しで、ナンピン禁止の (銘柄, 側, **戦略**) キーがエントリー経路で join なしに引けるようにするためのもの。`'' = 戦略不明`(external / 旧建玉)は**全戦略をブロックする**側に倒す。 `split_factor` / `split_adjusted_on`(0022)は株式分割(併合)の権利落ちで建玉を言い直した記録(累積の株数倍率・最後に言い直した日)。言い直しは株数 ×r・円/株の凍結値 ÷r(TP/SL 価格は呼値へ丸め)で**損益は不変** = config 凍結の例外ではなく同じ凍結値を新しい単位で書き直すだけ。paper は権利落ちの値段(値幅制限の外 かつ 単純分割比)で、live は broker の建玉照会(株数・建単価)で確かめてから書く(`command.SplitGuard` / `RearmUnguarded`)。
- **trades** — 往復台帳。`profit_loss_jpy` は GROSS、`fee_jpy`(正=コスト)/`carry_jpy`(受取=正)を分離し net は下流計算。`close_reason` の CHECK enum: `take_profit` / `stop_loss` / `max_hold` / `early_exit` / `ratchet_takeprofit` / `manual` / `reconcile_cold_close`(**値段すら観測できず時価で近似した**という記録の質のラベル。出口の種類ではない) / `broker_close`(**broker 側で決済されたが凍結 TP/SL のどちら側でもなかった**往復 — 人間がアプリで締めた / broker の都合。板の守りの約定は `stop_loss` / `take_profit` で書く) / `forced_flat`(引け前フラット)/ `entry_compensated`(約定した**後**に守りを board に置けず entry saga が巻き戻した往復・migration 0011)/ `external_close`(人間が建てた external 建玉の決済・migration 0012)/ `ratchet_giveback_loss`(トレール決済のうち **gross が負**だったもの・migration 0013。判定は側に依らない gross の符号で、価格比較では SELL 建玉で逆になる。**これは戦略の出口なのでエッジ標本に入る**)/ `split_misfire`(**株式分割の権利落ちを損切り/利確と誤読して決済した**往復・migration 0022。株数・値段は分割調整後で記録。**戦略の出口ではない**)/ `harvest_expiry`(**後から課した保有期限**による打ち切り・migration 0018。旧 enum 値で、これを出すコード経路は無い。`max_hold`(建玉時に戦略が決めた出口)と分けるのは、人間が課した検閲標本だから。**戦略の出口としては数える**ので `IsNonStrategyClose` には足さない)。**`entry_compensated` / `external_close` / `split_misfire` の 3 つだけが戦略の出口ではない**ので**エッジ判定からだけ**除外する(判定は `port.IsNonStrategyClose`・件数は `compensated_n` / `external_n` に残す)。**画面の戦績と引け後パケットは口座ベース**で、普通のトレードとして戦略に計上する。**増やす時は migration の CHECK 拡張 + `port` の string を同時更新**。
- **candles** — OHLCV(backtest/replay 用)。`(symbol, interval, open_time)` PK。
- **signal_rejections** — gate reject の監査(「なぜエントリーしなかったか」の再起動を跨ぐ trail)。書き込みは `TradingCycle.recordRejection`(全 reject 経路・best-effort)。`config_id` は空なら NULL。**エッジ記録**: 同一 (symbol, reason 種別) の連続 reject は書かない(毎 tick 連打で行数が爆発する)。`reason` = 安定種別(先頭トークン)・`detail`(0009)= 可変部。0009 以前の行は旧形式(reason に全文)。live の selector も**発火した候補を arm しなかった理由**を `selector_` 前置で書く(`selector_risk_per_trade` / `selector_notional_over_cap` / `selector_gross_notional_cap` / `selector_manual_symbol_block` / `selector_arm_cfg_nil`。`app.Selector.notArmed`・同じエッジ記録・arm したらエッジを閉じる)。ゲートの行と区別できるので、「arm されなかった」と「arm されたが発注前で落ちた」を同じ表で読む。
- **screen_snapshots**(0008)— LLM ラウンドごとの全銘柄 × 全スクリーナーの screen 結果(`triggered` / `score` / `picked` = 枠を得たか / **`side`**(0017)= 入口が成立した向き。空 = 買い専用スクリーナー)。書き込みは `AdvisorLoop.persistScreenSnapshots`(COPY・best-effort)。監査/検定専用 — 取引経路は読まない。約 1,776 行/ラウンド・35,000 行/日。
- **advisor_runs** — LLM advisor(config 生成ループ)の全 run 監査。成功/失敗を問わず 1 run 1 行: `input_json`(LLM が見た summary)/ `output_yaml`(生 stdout)/ `parsed_yaml` と、LLM が述べた判断理由(`regime_type` / `regime_confidence` / `regime_reason`)。`status` CHECK enum: `success` / `cli_error` / `parse_error` / `timeout` / `empty_output`(**`port.AdvisorRunStatus` と同時に拡張**)。`model` は生成した LLM 世代(`claude-opus-5` 等。migration 0004 で追加。空 = 不明 — 0004 以前の行や CLI が JSON envelope を返さなかった run。CLI は素のテキスト出力ではモデル名を報告しないため `--output-format json` の `modelUsage` から取得している)。**observability 専用**で取引経路は一切読まない(FK なし・書込失敗は取引を止めない)。

## junction テーブル(NULL 回避・状態依存属性の隔離)
- `positions_live` は 0019 で削除した(守りの取消は板 `ListProtectiveOrders` を正とし、台帳の写しは読まれない)。

## 不変条件
- `ClaimForClose` は `WHERE status='OPEN'` のみ成功(CAS、二重 close 防止)。
- **出口幾何は円/株**(migration 0006)。呼値は銘柄と価格帯で 0.1〜10円に変わるため、tick 建てだと同じ config が銘柄ごとに別の賭けになる。呼値が要るのは「発注価格をグリッドに丸める」ときだけ。`take_profit_price` / `stop_loss_price` は約定値に幅を足して確定した絶対価格で、broker の OCO に入っている値段と同一 — `EvaluateExit` もこれと現在値を直接比べる。0 = その脚は無い(外部採用建玉など)。
- **建玉が開いている間 `broker_position_id` は一意**(migration 0005 の部分 UNIQUE index)。broker 側の 1 建玉 = 1 id なので重複は必ず bug で、重複したまま決済すると別銘柄の建玉を閉じて `trades` に別銘柄の値段が入る。CLOSED 行は対象外(決済済み id は誰も参照しない)。paper では起動時に `adoptPaperBook` が台帳から紙帳簿を復元し、採番 seq を復元 id の先へ進めることで重複を作らない。
- close saga(CLOSING→CLOSED + trade row)は 1 トランザクション(in-memory では `Closer` がロック内で原子化)。
- `close_reason` enum を増やす時は migration で CHECK 拡張 + port の string 同期。
